### 2.2 Thèse (page dédiée)
- **Titre :** *AI-Driven Model-Based Systems Engineering for Industrial Cyber-Physical Systems*
- **Question :** comment des agents IA peuvent-ils permettre une adoption effective du MBSE tout au long du cycle de vie des CPS industriels ?
- **Directeur :** Pr. Ernesto Exposito (LIUPPA) · ED 211 · déc. 2025 → nov. 2028
- **Trajectoire de recherche** (frise à 4 temps, tirée du bilan de maturation) :
  1. *Cadrage* : où insérer l'IA dans le cycle de vie (pipeline P1–P5).
  2. *ARISE* : générer et structurer les exigences à partir de documents d'ingénierie, évalué sur le projet européen SAFE (Digital Europe Programme).

## 4. Exigences fonctionnelles
- **F1. Bilingue FR/EN**, avec un sélecteur et des URL distinctes (`/en/`).
- **F1 bis. Mode clair et mode sombre**, avec un bouton qui alterne clair / sombre, mémorisé chez le visiteur. Le clair est le mode par défaut (pas de mode « auto »).
- **F1 ter. CV téléchargeable** : version publique en PDF (anglais, 2 pages) sans téléphone ni e-mail, servie depuis `public/cv/arona-fall-cv.pdf`. Liens sur l'accueil, la page Expériences et la page Contact.
- **F2. Contenu en MDX ou JSON** (collections typées). Ajouter un projet ou une publication ne demande pas de toucher au code.
- **F3. Filtre des projets** par pilier et par technologie.
- **F4. CV téléchargeable**, généré par `/ats-latex-cv` à partir des mêmes données que le site.
- **F5. Publications** : BibTeX copiable, lien DOI, PDF auteur si l'éditeur l'autorise.
- **F6. Une pièce interactive maîtresse** : un schéma des couches Arcadia (OA→SA→LA→PA) qui sert aussi à présenter le parcours. Pas de schéma d'architecture interne à Alouette.
- **F7. Contact** par formulaire sans exposer l'e-mail (Formspree ou fonction serverless).

## 5. Exigences non fonctionnelles
- Lighthouse ≥ 95 sur les 4 axes · LCP < 1,5 s · page d'accueil < 200 Ko de JS
- WCAG 2.2 AA · `prefers-reduced-motion` respecté · thème clair et sombre
- SEO : JSON-LD `Person` + `ScholarlyArticle`, Open Graph par page, sitemap
- **Hébergement : GitHub Pages** sur `https://rachidusfallensis.github.io`, avec le dépôt `Rachidusfallensis.github.io`, ce qui donne une URL racine sans sous-chemin. Déploiement par GitHub Actions (`withastro/action`) à chaque push sur `main`. Un domaine perso pourra s'ajouter plus tard avec un fichier `CNAME`.
- Le site étant entièrement statique, le formulaire de contact passe par **Formspree** (offre gratuite) ou se remplace par un lien `mailto` masqué.

**Stack recommandée : Astro + MDX + Tailwind**, avec quelques îlots React pour la pièce interactive. C'est un site de contenu : Astro livre presque zéro JS, gère l'i18n, propose des content collections typées et s'exporte en statique, ce qui convient bien à GitHub Pages.
